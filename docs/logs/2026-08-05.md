# 2026-08-05 - 登录 / 握手协议落地，跨用户转发前置条件齐备

> 新增 `Opcode::login`（线上字节 3），登录帧复用 `Message` 结构；`Controller` 注入静态用户表，`auth(uid, credential)` 真实查表；登录成功绑定 fd ↔ uid 并回 `response(ok)`，失败回 `response(fail)` 且连接保留可重试；accept 阶段不再注册任何 uid，`core` 的 `auth_handler_` / `register_handler_` 回调退役；未登录连接发非登录帧一律拒绝并记日志。调试客户端新增 m7 登录模式，M1-M6 加登录前置保持传输层断言语义。ctest 10/10 全 PASS，端到端联调六路验证通过。

## 概览

- 协议设计三决策拍板：帧形态选**新 `Opcode::login`**（非 request + msg_type 变体）；认证选**静态密码表**（`Controller` 构造注入，`main.cpp` 演示表）；失败处置选**回 fail 可重试**。
- 登录驱动归协调层（`architecture.md` §3.4「绑定发生在登录时，不在 accept 时」兑现）：`core.cpp:118` 的 `register_handler_("guest", client_fd)` 删除，`core` 的 `auth_handler_` / `register_handler_` 两个回调整体退役——它们是登录协议落地前的临时接法，留着就是两条没人调的死路径（8/4 日志 §4.5 判空未调用同步消除）。
- 未登录强制：`UsersGroup` 新增 `has_fd(fd)` 连接级登录态查询；`Controller::process` 对非 login 帧先查登录态，未登录一律拒绝并记日志。

## 1. 协议设计

### 1.1 登录帧形态

- `Opcode::login = 3`（`src/common/binary_code.h`），`is_known_opcode` 同步扩展——decoder 对 login 帧零特殊处理，只靠枚举值域校验放行。
- 登录帧复用 `Message` 结构：`from_uid_` = 待登录 uid，`content_` = 凭证，`to_uid_` 填自身过 `is_valid()` 闸（`Message::is_valid()` 要求全部字段非空，decoder.h:67 全局校验，不为登录帧开例外）。
- 登录响应 = `response` 帧：成功 `status=ok`、失败 `status=fail`，帧体原样回显入站 Message（客户端凭帧头 status 判断，凭帧体核对 uid）。

### 1.2 认证与绑定

- `Controller` 构造新增 `UserTable users = {}` 参数（`std::unordered_map<std::string, std::string>`，uid → 凭证），`auth` 从 static 恒 true 改为成员方法查表比对。
- 登录帧处理（`controller.cpp` login 分支）：`auth(from_uid_, content_)` → 成功 `register_user(uid, fd)` 绑定 + `response(ok)`；失败 `response(fail)`、不绑定、连接保留（可重试，防爆破挂 TODO）。
- `main.cpp` 演示用户表：`alice/alice123`、`bob/bob456`，注释标明真实认证（数据库 / 外部鉴权）落地前先静态查表。

### 1.3 连接生命周期收敛

- accept 阶段匿名（`core.cpp` handle_accept 删除判空 + guest 注册，保留「New client connected」日志）。
- 未登录连接发 request / ack → 拒绝 + `[controller] reject frame (opcode=N) from unauthenticated fd N` 日志，连接不关。
- 断开解绑已有（`disconnect_handler` → `delete_fd(fd)`），未登录 fd 不在表内，`delete_fd` 安全返回 false。

## 4. 审查发现的问题

以下为本次改动范围内的遗留点，均未处理（按要求仅记录）：

### 4.1 登录凭证明文传输

`content_` 明文携带密码，TCP 无 TLS。演示阶段可接受，真实部署前必须上加密通道或换 token 机制。TODO 未单列，随真实认证一并设计。

### 4.2 登录失败无次数限制

「fail 可重试」决策下连接可无限重试登录，无防爆破（次数限制 / 拉黑）。最终明确「防爆破挂 TODO 后续做」——TODO.md 未单列，需要补记。

### 4.3 `assemble_ack` 的 `status` 语义未随登录协议统一

ack 应答帧头保持入站原样（8/4 已有记录），登录响应帧显式写 status。两处应答的 status 语义一致性未收口。

### 4.4 login 帧 `to_uid_` 填自身的约定散落三处

客户端 m7、pre_login、test_controller 工厂各自约定 `to_uid_ = uid`。协议文档（architecture.md §2.x）未写这条约定，将来客户端实现需要统一出处。

### 4.5 重复登录未处理

已登录连接再发 login 帧：`register_user` 幂等（保留首次 fd），回 `response(ok)`。语义上是「重复登录成功」，无告警。单 uid 多 fd 向量化后此路径需要重新审视。
