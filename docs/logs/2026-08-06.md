# 2026-08-06 - User fd 向量化、双客户端联调体系、登录三态收敛、core 出队归因修正

> `User::fd_` 标量 → `fds_` 向量，一 uid 多设备的数据结构落地，`delete_fd` 从整用户全删改为按设备摘除；`UsersGroup::register_user` 从二值 bool → 三态 `RegisterResult`（Registered / AlreadyBound / FdConflict），同 fd 改登另一 uid 被明确拒绝；`Controller` 透传三态，登录冲突回 `response(fail)` 且原绑定不变；`assemble_response` 收 `Status` 参数不再恒置 ok，request 路由失败回 `response(fail)`；`core` 出队循环三种失败模式归因分离——目标已死 / 编码失败只丢条目不杀连接，写目标失败杀的是目标而非发送方；调试客户端新增 M8-M10 双进程场景，`assembler.cpp` 退役（实现内联到头文件），测试同步扩展：UsersGroup 随机属性测试 5000 ops、Controller 改绑场景、Assembler fail 回归。

## 概览

- **数据结构**：`User` 内部 `fd_` 标量改为 `fds_` 向量，`get_fd()` 取 `fds_[0]`、`add()` 追加、`delete_device()` 线性擦除、`vec()` 暴露引用。`users_group.cpp` 空壳文件删除。
- **路由表三态**：`RegisterResult` 枚举（Registered / AlreadyBound / FdConflict），`register_user` 先分类、后提交（无半提交窗口），`delete_fd` 按设备擦除、最后一个 fd 断开才清除整条 User。`invariants_ok()` 正向 + 反向双向扫描校验双表一致性。
- **登录行为**：同 fd 重复登录同 uid → AlreadyBound（幂等成功，不回 fail）；同 fd 改登另一 uid → FdConflict（拒绝，原绑定不变，连接保留可重试）。两处决定由 `UsersGroup` 集中、`Controller` 透传并在 login 分支据此回 ok/fail。
- **响应帧头 status**：`assemble_response` 不再恒置 `Status::ok`，改为收调用方传入的 `st`。`Controller::process` 对 request 先查路由：在线 → `ok` + 转发入队；不在线 → `fail` + 打日志、不转发。发送方终于能区分「已投递」与「目标不在线」。
- **core 出队归因**（D3 决策）：三种失败 → 三种处置。(1) 目标已死 / pending_close → 丢条目，continue；(2) 编码失败 → 丢条目，continue；(3) 写目标失败 → 杀目标 `close_client(to_fd)`，continue（自发自收除外，回落 `fatal = true; break`）。此前一律 `fatal = true; break`，杀的是发送方，且丢弃剩余出队条目，把发送方自己的 response 也吞了。
- **测试客户端**：M8-M10 双进程场景——两个客户端进程以不同 uid 登录，M10 向对端发 request，M8/M9 作为对端收帧。M9 停读变体可把服务端写缓冲顶过 1MiB 高水位。
- **测试同步**：test_users_group 增 AlreadyBound / FdConflict / 多设备 / 随机属性测试（5000 ops vs 朴素模型）；test_controller 增改绑拒绝场景 + request 目标不在线回 fail 断言；test_assembler 增 `Status::fail` 回归。

## 1. User fd 向量化（commit 2e315b2）

### 1.1 User 类

- `int fd_` → `std::vector<int> fds_`；`#include <algorithm>` + `<vector>`。
- 默认构造改为空向量（`User() = default`），单 fd 构造改为 `fds_.push_back(fd)`。
- `get_fd(int& fd) const`：取 `fds_[0]`（目前投递面向连接而非设备，调用方不指定 device_id）。
- `add(int fd)`：`fds_.push_back(fd)`。
- `delete_device(int fd)`：`std::find` → 未找到返回 false → `fds_.erase(it)`。
- `vec()` / `vec() const`：暴露向量引用。
- 旧单 fd 代码已注释保留（`// int fd_ = -1;`、`// bool get_fd(int& fd) const {...}`）。

### 1.2 UsersGroup 适配

- `register_user`：uid 首次出现 `try_emplace(uid, fd)`，已存在 `uid_to_fd_[uid].add(fd)`。
- `delete_fd`：`user.delete_device(fd)` 摘除单设备 → `user.vec().size() == 1` 时才 `delete_user(uid)`（整条清除）。
- `users_group.cpp`（空壳，仅含 namespace 闭合花括号）删除——`UsersGroup` 已是全 header-only。

## 2. 双客户端测试体系（commit 92fbb1c）

### 2.1 调试客户端 M8-M10

`src/client/main.cpp` +387 −62，新增三种双进程模式：

| 模式 | 角色 | 行为 |
|------|------|------|
| M8 | 接收方 | 登录后以 1s tick 持续 recv 并打印帧体（前 128B），驻留 hold_sec 后返回「至少收到一帧且未被关 → 0」 |
| M9 | 接收方（停读变体） | 登录后永不 recv，内核接收缓冲填满后通告零窗口，服务端 write_buf_ 堆到 1MiB 高水位 → 唯一可从客户端触发的「写目标失败」路径 |
| M10 | 发送方 | 向 peer_uid 连发 count 条 request（默认 1 条 / 64B），非阻塞 send + poll，边发边 `pump_inbound` 排空自身入站帧，发完驻留 hold_sec 观察本连接是否被牵连关闭 |

关键新增函数：

- `pre_login(fd, uid, credential, out_status)`：签名变更，`out_status` 回写帧头 status 字节（M8-M10 据此拒绝带病继续，M1-M6 不看它）。
- `login_as(fd, uid, credential)`：登录必须成功，否则直接判死。
- `drain_frames(acc, count, label, body_cap)`：签名扩展——label 区分 echo/recv，body_cap 限制帧体打印字节数（kNoBodyCap = 全打，kBriefBodyBytes = 128）。
- `pump_inbound(fd, acc, in_count)`：非阻塞排空入站字节并解帧，返回 false = 对端已关。
- `run_receiver(fd, keep_reading, hold_sec)`：M8/M9 共用驻留循环。
- `run_sender(fd, uid, peer_uid, count, content_bytes, hold_sec)`：非阻塞交替 send/recv 循环。
- `make_padded_content(index, content_bytes)`：前缀 `s4a-<N>` + 'A' 填充。
- `parse_uint(s, out)`：十进制无符号解析（空串 / 非数字 / 溢出 → false）。

CLI 参数解析重构：`--mode` / `--mode=` / 直接传模式三种写法统一收集位置参数到 `std::vector<std::string> args`，各模式按需读取。

## 3. 登录三态 + core 出队归因修正（commit 35d8729）

核心 commit（8 文件，+289 −73），数据结构向量化之后的行为层收口。

### 3.1 UsersGroup 三态注册

- 新增 `enum class [[nodiscard]] RegisterResult { Registered, AlreadyBound, FdConflict }`。
- `register_user` 从 `bool` 改为返回 `RegisterResult`：
  - **分类阶段**（只查不改）：`fd_to_uid_.find(fd)` → 已存在 + 同 uid → AlreadyBound；已存在 + 不同 uid → FdConflict。
  - **提交阶段**（两次插入都必然成功）：`fd_to_uid_.emplace(fd, uid)` → `uid_to_fd_.try_emplace(uid, fd)` 或 `add(fd)`。
  - 不再 `noexcept`（提交阶段会分配内存）；有意不写 OOM 回滚——进程无 OOM 恢复路径。
- `delete_fd`：按值取 uid（防引用悬垂）→ 查表 → 删 fd 表条目 → `delete_device(fd)` → 向量空则 erase User。`assert(invariants_ok())` 守尾。
- `invariants_ok()`：正向（uid → fd）+ 反向（fd → uid）双向扫描，禁止空向量 User、禁止孤儿 fd、禁止重复登记（hits != 1）。设计注释详述为何单向扫描不够——两类错误可成对抵消。

### 3.2 Controller 登录分支

- `register_user` 返回类型从 `bool` → `RegisterResult`，签名透传到 `controller.h`。
- `process` login 分支：switch on `register_user` 返回值：
  - `Registered` / `AlreadyBound` → `ok = true`（登录成功）
  - `FdConflict` → `ok = false`，打日志 `[controller] reject login as "<uid>" on fd <N>: already bound to another uid`，原绑定不变
- 不写 `default:`，靠 `-Wswitch-enum` 提醒新增枚举值时同步扩展。

### 3.3 Controller request 分支

- 先查路由、再装配响应：顺序不可颠倒——响应的 status 取决于目标是否在线。
- 在线：`assemble_response(rmp, Status::ok, assembled)` + `out_queue.emplace_back(rmp, to_fd)`。
- 不在线：`assemble_response(rmp, Status::fail, assembled)` + 打日志 `[controller] drop request ... peer not online`，不转发。

### 3.4 Assembler::assemble_response 签名

- `assemble_response(const MessagePack& in, types::Status st, vector<MessagePack>& out)`：新增 `st` 参数，不再恒置 `Status::ok`。
- 注释明确：有意不给默认值——默认 ok 等价于保留旧行为，而那正是本参数要修的缺陷。

### 3.5 Core 出队循环（D3 决策）

三种失败模式、三种处置、共同硬约束——除自发自收外一律 `continue`，绝不 `break`：

| 失败模式 | 判定条件 | 处置 | 理由 |
|----------|----------|------|------|
| ① 目标已死 | `conns_.find(to_fd) == end` 或 `is_pending_close(to_fd)` | `continue`，只记日志 | 发送方无过错，杀谁都是错误归因 |
| ② 编码失败 | `encode()` 返回非 ok | `continue`，只记日志 | encode 出错后置条件保证一字节未动，半帧不上线 |
| ③ 写目标失败 | `send()` 返回 closed/error | 杀目标 `close_client(to_fd)`，`continue` | 账记在目标头上。自发自收（to_fd == fd）回落 `fatal = true; break` 走唯一入站杀点 |

此前一律 `fatal = true; break` 的后果：(a) 杀的总是发送方（错误归因）；(b) 跳出循环丢弃剩余出队条目，吞掉发送方自己的 response（controller 先入转发、后入 assembled，一条转发失败就 break 会把排在后面的回执一并丢掉）。

新增 `is_pending_close(fd)`：`pending_close_` 至多容纳一个 epoll 批次（≤ 64），线性扫描即可。同时用于 `run()` 事件循环的跳过判定，替代旧的内联 for 循环。

`close_client` 新增幂等护栏：同一 fd 重复入队会让 `drain_pending_close()` 对它触发两次 `disconnect_handler_`（第二次作用在可能已被新连接复用的 fd 号上）。自发自收正是「杀目标」与「杀入站」两条杀路收敛到同一 fd 的地方——唯一性由幂等护栏保证，不靠调用方各自做情形分析。

### 3.6 User 类微调

- `get_fd` 签名简化为 `get_fd(int& fd) const`（删除 `device_id` 参数）：保留一个没有调用方能有意义传入的参数只会把「分支为空却返回 true」这类契约违规留在原地。
- 新增 `vec() const` 常引用重载，供 `invariants_ok()` 等 const 场景使用。
- `CMakeLists.txt` +47 行（测试目标配置更新）。

## 7. 审查发现的问题

以下为本次改动范围内的遗留点：

### 7.1 `invariants_ok()` 仅在 assert 与测试中调用

`register_user` 和 `delete_fd` 末尾的 `assert(invariants_ok())` 在 NDEBUG 构建下整个消失。`invariants_ok()` 本身是 O(n) 扫描（嵌套线性），设计注释明确「只在 assert 与测试里跑」——生产路径上双表一致性靠代码正确性保证，没有被运行时持续校验。

### 7.2 OOM 回滚缺失

`register_user` 提交阶段的两次插入之间若抛 `bad_alloc`，两表会不一致。注释明确「有意接受该后果为致命错误，不写回滚」——进程无 OOM 恢复路径。

### 7.3 客户端帧体打印截断

M8-M10 帧体只打印前 128 字节（`kBriefBodyBytes`），帧体 > 128B 时尾部被省略。联调时需对照序号（`s4a-<N>` 前缀）逐帧对号，无法肉眼比对完整帧体。

### 7.4 M9 停读的硬时长假定

`run_receiver` 的停读路径以 `kTickSec = 1s` 为片睡眠，驻留秒数由命令行给出。若发送方在驻留期满后才启动，写缓冲尚未堆过高水位，无法触发「写目标失败」路径。反过来驻留过长则是白白占用端口。

### 7.5 `User::fds_` 只取 `[0]`

`get_fd()` 永远返回 `fds_[0]`，多设备扇出时需改为 `get_fds(vector<int>&)`。当前无调用方需要多设备遍历，暂不落地。
