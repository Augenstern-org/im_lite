## 2. 提交 `93dc9fc` — UsersGroup 支持注销，正式接线（14 文件，+500 −48）

### 2.1 users_group.h — 双向映射 + fd-keyed 删除

- `group_` 拆分为 `uid_to_fd_`（`unordered_map<string, User>`）与 `fd_to_uid_`（`unordered_map<int, string>`）两表。
- `register_user` 改写为同时写入两表：`fd_to_uid_.emplace(fd, uid)` → `uid_to_fd_.try_emplace(uid, fd)`。返回类型从 `void` 改为 `bool`（恒 true）。
- `delete_fd` 签名从 `delete_fd(uid)` 改为 `delete_fd(int fd)`：先查 `fd_to_uid_` 反查 uid，再查 `uid_to_fd_` 确认存在，然后先删 `fd_to_uid_` 再调 `delete_user(uid)` 删 `uid_to_fd_`。注释标明「在这行之后需保证不会出现异常」——`fd_to_uid_.erase` 后不再有抛异常路径，保证两表不出现「fd 表已删但 uid 表残留」的半状态。
- `delete_user` 加 `noexcept`，内部调用 `uid_to_fd_.at(uid).get_fd(fd)`（冗余的存在性检查，`fd` 变量未被使用，见 §4）。
- 类注释补充「详见 TODO.md」。

### 2.2 user.h — delete_device 落地

- 新增 `delete_device(int fd)`：当前忽略 `fd` 参数，设 `fd_ = -1` 并返回 true。`fds_.erase(fd)` 以注释保留，等向量化后替换。

## 4. 审查发现的问题

以下为本次改动范围内的问题，均未修改（按要求仅记录，不擅自解决）：

### 4.1 `users_group.h:23-26` delete_user — 死代码

```cpp
int fd = -1;
uid_to_fd_.at(uid).get_fd(fd);  // fd 写入后从未读取
```

`fd` 由 `get_fd` 写入但后续从未使用。该行仅作为存在性检查（`at()` 在 uid 不存在时抛异常），但调用方 `delete_fd` 已在 `:48` 通过 `find` 确认 uid 存在。冗余，非 bug，但应清理。

### 4.2 `users_group.h:31-38` register_user — 恒返回 true

两条路径均 `return true`，`try_emplace` 的 `.second` 不改变返回值。调用方无法区分「新注册」与「已存在」。当前设计可能有意（注释「fd 始终唯一」），但与 TODO.md 的多线程规划存在潜在冲突。

### 4.3 `users_group.h:31-38` register_user — 同 uid 不同 fd 的状态不一致

若 uid "alice" 已注册 fd=42，再调用 `register_user("alice", 99)`：
- `fd_to_uid_.emplace(99, "alice")` 成功（99 是新 fd）
- `uid_to_fd_.try_emplace("alice", 99)` 失败（alice 已存在），**保留**旧 `User(fd=42)`
- 结果：`fd_to_uid_[99] = "alice"`，但 `query("alice")` 返回 42
- 后续 `delete_fd(99)` 执行：查 `fd_to_uid_[99]`→得 "alice" → 查 `uid_to_fd_["alice"]`→存在 → 删 `fd_to_uid_[99]` → `delete_user("alice")` 删 `uid_to_fd_["alice"]`
- 此时 `fd_to_uid_[42]` 仍指向 "alice"（**孤儿条目**），而 `uid_to_fd_` 中 alice 已消失

当前 `register_handler_("guest", ...)` 将所有连接注册为同一 uid 可触发此路径的退化形式（同一 uid 反复注册不同 fd——第一个注册建立 `User(fd=first)`，后续 `try_emplace` 全失败，`fd_to_uid_` 持续膨胀但 `uid_to_fd_` 只记第一个 fd）。向量化（一 uid 多 fd）落地后会自然解决此问题。

### 4.4 `user.h:37-40` delete_device — 忽略 fd 参数

`delete_device(int fd)` 完全忽略参数，始终设 `fd_ = -1`。注释已标明向量化前的占位实现。

### 4.5 `core.cpp:116` — auth_handler_ 判空但从未调用

`auth_handler_` 的 nullptr 检查存在，但 `handle_accept` 内及后续代码中没有任何地方调用 `auth_handler_`。注释「目前还没写好，详见 TODO.md」承认此为占位。

### 4.6 `controller.cpp:56` — 注释过时（继承自 8/3）

「目前所有出站帧的目标 fd 恒等于入站 fd」——转发通路落地后，request 分支的转发帧目标 fd 可以是其他用户的 fd（`out_queue.emplace_back(rmp, to_fd)`）。8/3 日志 §7.2 已标为「注释过时两处」之一，未随本提交修复。

### 4.7 `test_assembler.cpp:95-106` — 空测试用例

「assemble_response 不修改入站 MessagePack」测试体为 `(void)orig_opcode;` ——实际未执行任何断言。注释自述原因：入站参数是 `const&`，物理上不可能被修改，原测试意图无法表达。用例保留为意图文档，不产生验证价值。
