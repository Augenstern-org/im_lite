## 3. S3 — EPOLLIN 分支重写为 drain 循环（core.cpp）

`core.cpp:149-217` 按 §4.4 伪代码重写：

```
while (!in.empty()) {
    dst = decode(in, rmp);
    if (dst == incomplete) break;              // 唯一「保留字节」的出口
    if (dst != ok)        { fatal = true; break; }

    consumed = FrameHeader::wire_size + rmp.fh_.body_len_;
    in.erase(in.begin(), in.begin() + consumed);   // 先推进，再派发

    send_queue.clear();
    if (message_handler_) message_handler_(fd, rmp, send_queue);   // 回调判空（三连②）

    for (auto& item : send_queue) { encode → send; 失败则 fatal = true; break; }
    if (fatal) break;
}
if (fatal || rst == error || (rst == closed && !conn.want_write())) { close_client(fd); return; }
```

- **四条承重理由落为注释（:155-168）**：不设帧数上限 drain 到 incomplete（LT + `kReadSoftCap` 64KiB 是唯一量化闸）；`erase` 先于 handler（`main.cpp:39-43` 的 try/catch 包着 `run()`，handler 抛异常栈展开时毒帧已出局，否则 livelock）；循环体内 close_client 调用点为零、所有杀决策走 `fatal = true; break;`；不加读缓冲上限（恒界 ≤69631 可推导：残留 ≤65535 + 每轮 append ≤4096 且 `size() >= 65536` 即返回）。
- `in.clear()` 在 `handle_client` 内**零残留**——旧「send_queue 非空则清空」语义及其「不可无条件清空（半帧重组）」的旧注释整段删除，由新说明取代：字节消费改由 ok 路径精确 `erase` 承担，重组由 `incomplete` + 保留字节的 break 出口承担。
- close_client 调用点 **6 → 3**（:136 HUP/ERR、:144 EPOLLOUT、EPOLLIN 尾部），`update_events` 内 :229 属另一函数未动。
- 解码契约内联进注释（:179-181）：当且仅当 `decode()` 返回 `ok` 时本帧消耗 `wire_size + body_len_` 字节，其余返回值下该表达式无定义（code-review 修正：原注释外指 io_status.h，而契约只存在于设计文档——改为内联）。

## 4. S4 — 客户端多帧测试模式（client/main.cpp）

- 重写为命令行可选模式：`client [--mode m1|m2|m3|m4|m5|m6]`（m1 无参数默认；也支持 `--mode=m2` / 裸 `m2`；用法错误退出码 2）。m2 与 m3 映射同一行为（一次 `send()` 两帧），区别在服务端侧验证点（粘包丢帧 vs LT stall）。
- 各模式发送形态：m1 单帧回显；m2/m3 两帧拼接一次 send（Cirno/20011229 + Daiyousei/20011230，便于人工比对），期望恰好 2 个回显且 5s 超时内到达；m4 先发 6B 帧头 + 8B 帧体，sleep 1.5s 再发剩余，期望恰好 1 个回显（验证 `incomplete` 不消耗字节）；m5 空 `content_` 帧 + 合法帧一次 send，期待连接被关（EOF/ECONNRESET 视为预期）；m6 手工 6 字节帧 opcode=0x07（枚举外），期待连接被杀。
- **开发过程踩坑**：首版计数逻辑有 bug——`drain_frames` 的 `parsed` 是单次调用局部变量，两帧分两个 TCP 段到达时每轮 recv 重新归零，got 永不达 2，只能等 5s 超时；实测首轮 M2 显示两帧都收到却报「got 1 of 2」，且帧序号打印两个 `#1`。修复：`drain_frames` 改为跨调用累计 `count`，`count >= want` 立即返回。顺带修复 m2/m3 分支日志标签拼成 `[mm2]` 的问题。
- code-review 一条 nit：`count >= want` 返回使「恰好两个」语义实际是「至少两个」（两帧后跟残留半帧也会 PASS）——M2/M3 判定补 `acc.empty()` 断言，日志改为 "exactly 2 complete echoes, no residual bytes"。
